# Web Design & Frontend Quality Standard

You are building websites for real businesses. The final result must feel intentionally designed by a professional web designer/developer, not generated from a generic AI template.

## Core Principle

Do not optimize for "adding more content." Optimize for:

* strong visual hierarchy
* clear communication
* credibility
* conversion
* memorable visual identity
* excellent spacing and typography
* simplicity
* responsiveness
* polished interactions

Every element must have a reason to exist.

## STRICTLY AVOID

Do NOT use:

* Emojis unless explicitly requested
* Generic AI-style copy
* Generic hero sections
* "Welcome to [Business]"
* "We are passionate about..."
* Fake statistics
* Lorem ipsum
* Unnecessary sections
* Excessive cards
* Excessive rounded containers
* Excessive pills/badges
* Random gradients
* Purple/blue AI-looking gradients
* Generic glassmorphism
* Decorative elements with no purpose
* Huge text just because it looks impressive
* Repetitive CTA buttons
* Generic stock-photo layouts
* Overuse of shadows
* Overuse of borders
* Template-like layouts that could belong to any business

The website must NOT look like a website generated from a standard SaaS/AI template.

## DESIGN PROCESS

Before writing substantial frontend code:

1. Identify the business.
2. Identify its target customer.
3. Identify the primary action we want visitors to take.
4. Determine the appropriate visual personality.
5. Establish a coherent typography system.
6. Establish a restrained color palette.
7. Determine the layout and visual hierarchy.
8. Decide which sections are actually necessary.

Do not start by blindly generating a standard collection of:

Hero → Features → Testimonials → Pricing → FAQ → CTA → Footer.

Only use sections that make sense for the specific business.

## VISUAL DESIGN

Use professional principles of:

* typography
* spacing
* grid systems
* contrast
* alignment
* visual hierarchy
* whitespace
* composition
* consistency

Prefer fewer, stronger elements over many weak elements.

A section should feel deliberately composed rather than assembled from components.

Typography should have clear hierarchy between:

* display/headline
* subheading
* body
* labels
* navigation
* CTA

Do not use excessive font sizes, weights, or styles.

## BRANDING

The design should reflect the actual business.

For example:

A high-end restaurant may benefit from:

* editorial typography
* strong photography
* restrained colors
* sophisticated spacing
* subtle motion

A car workshop may benefit from:

* strong typography
* technical visual language
* high contrast
* bold photography
* clear service hierarchy

A law firm may benefit from:

* restrained typography
* credibility
* whitespace
* conservative visual language

Do not apply the same design language to every client.

## COPY

Write concise, believable copy appropriate to the business.

Never use generic AI phrases simply because they sound professional.

Bad:
"Experience excellence with our innovative solutions."

Better:
Use specific language describing what the business actually offers, who it serves, and why someone should choose it.

If information about the business is unknown, do not invent facts that could be misleading.

## COMPONENTS

Create reusable components when appropriate, but do not force everything into cards.

Use:

* sections
* grids
* typography
* imagery
* buttons
* navigation
* forms
* lists
* editorial layouts

based on what the content requires.

Components should support the design rather than determine the design.

## ANIMATION

Use motion sparingly and intentionally.

Good:

* subtle entrance animations
* smooth hover states
* image transitions
* navigation transitions
* scroll-based reveals where appropriate

Bad:

* animations on everything
* excessive parallax
* distracting effects
* animations that slow down the website

Animation should make the website feel polished, not demonstrate that animation exists.

## IMAGES

Use imagery strategically.

Images should support the business and composition.

Do not fill empty space with random images.

If real images are unavailable, structure the design so that replacing the placeholder with real photography is easy.

## RESPONSIVE DESIGN

The website must be designed for:

* mobile
* tablet
* desktop

Do not simply shrink the desktop layout.

Consider how hierarchy, navigation, spacing, imagery and CTAs should change on smaller screens.

## ACCESSIBILITY

Use:

* semantic HTML
* appropriate heading hierarchy
* accessible buttons and links
* sufficient contrast
* keyboard-friendly interactions
* meaningful alt text

## CODE QUALITY

Write clean, maintainable frontend code.

Avoid unnecessary complexity.

Do not introduce dependencies unless they provide meaningful value.

Keep components understandable.

Do not sacrifice design quality for code convenience.

## FINAL QUALITY CHECK

Before considering the task complete, inspect the result as if you were a professional web designer reviewing a client deliverable.

Ask:

1. Does this look like a real business website?
2. Does it have a distinct visual identity?
3. Does it look generic or AI-generated?
4. Are there unnecessary sections?
5. Are there emojis or generic AI patterns?
6. Is the typography strong?
7. Is the spacing intentional?
8. Is the visual hierarchy obvious?
9. Is the primary CTA clear?
10. Does the mobile version feel designed rather than compressed?
11. Would a real business owner be proud to show this website to customers?

If the answer to any of these is no, improve the implementation before finishing.

## IMPORTANT

Do not merely follow the instructions literally.

Use professional design judgment.

When a design choice is ambiguous, choose the option that makes the website feel more specific, intentional, premium and appropriate to the actual business.
